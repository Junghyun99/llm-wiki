# Description: #todo/fill 태그가 달린 스텁 노트를 1개 골라 웹 검색으로 초안 작성 후 사용자 승인을 받아 저장합니다.

## 실행 파이프라인 (Execution Pipeline)
너는 지금부터 `/fill-stubs` 명령을 수행한다. **이번 실행에서는 스텁 1개만 처리한다.** 나머지는 다음 `/fill-stubs` 실행 시 순서대로 처리된다.

---

### Step 1 — 스텁 목록 스캔
`03_Wiki/` 내에서 `#todo/fill` 태그를 가진 파일을 grep으로 스캔한다.
```bash
grep -rl "todo/fill" 03_Wiki/
```
스텁이 없다면 "📭 처리할 스텁 노트가 없습니다."라고 출력하고 **종료**한다.

---

### Step 2 — 처리 대상 확정
발견된 스텁 목록 중 **첫 번째 파일**을 이번 실행의 처리 대상으로 자동 확정한다. 사용자 선택 없이 곧바로 Step 3으로 진행한다.

```
📋 미작성 스텁 노트 목록 (총 N개):
  1. `스텁노트1.md`  ← 이번 실행 대상
  2. `스텁노트2.md`
  3. `스텁노트3.md`
  ...
```

---

### Step 3 — 웹 검색 및 초안 작성
선택된 스텁 1개에 대해 아래를 수행한다.

1. 파일을 읽어 기존 내용과 YAML frontmatter를 파악한다.
2. 파일명 및 기존 내용에서 핵심 키워드를 추출하여 웹 검색을 수행한다.
3. 검색 결과를 종합하여 `extract-zettelkasten` 스킬의 **영구 노트 양식**에 맞는 초안을 작성한다.
4. 초안을 사용자에게 출력하고 승인을 요청한다.

```
🔍 `스텁노트명.md` 초안

[초안 내용 전체 출력]

**참조 출처:**
- 출처1 URL
- 출처2 URL

저장할까요? (승인 / 수정 요청 / 건너뛰기)
```

- **승인:** Step 4로 진행한다.
- **수정 요청:** 피드백을 반영하여 초안을 재작성하고 재승인을 요청한다.
- **건너뛰기:** 파일을 수정하지 않고 Step 6로 바로 진행한다.

---

### Step 4 — 원자성·사이즈 판정
승인된 초안이 **단일 원자적 개념**인지 판정한다. 아래 기준을 체크한다.

**단일 개념 (모두 충족 시 → Step 5A):**
- [ ] 모든 섹션이 하나의 개념명으로 수렴한다
- [ ] 세부 내용(공식, 코드, 표)이 해당 개념의 설명에 해당한다
- [ ] 다른 독립 개념은 내용으로 흡수하지 않고 `[[ ]]` 링크로만 참조한다

**복수 개념 (하나라도 해당 시 → Step 5B):**
- 두 개 이상의 독립적 개념이 병렬로 나열된다
- `extract-zettelkasten` 기준으로 3개 이상의 영구 노트로 분해 가능하다

판정 결과를 한 줄로 사용자에게 출력한다.
```
⚖️ 판정: [단일 개념 → 단일 노트 저장] 또는 [복수 개념 → Inbox 이동 후 분해]
```

---

### Step 5A — 단일 노트 저장
판정이 **단일 개념**인 경우에 수행한다.

승인된 초안을 스텁 파일에 덮어쓰고, YAML frontmatter의 `tags`에서 `todo/fill`을 제거한다.
Step 5A-1으로 진행한다.

---

### Step 5A-1 — 데드링크 스텁화
저장된 노트의 `[[링크]]`를 검사하여 존재하지 않는 대상을 스텁으로 자동 생성한다.
`extract-zettelkasten` 스킬 섹션 6과 동일한 스크립트를 사용한다.

```bash
python3 .claude/skills/extract-zettelkasten/scripts/check_dead_links.py \
  --files "저장된파일명.md" \
  --date "YYYY-MM-DD"
```

- **스텁이 생성된 경우:** `index.md`의 `## 🧠 영구 노트` 테이블에 아래 형식으로 항목을 추가한다.
  ```
  | [[스텁명]] | ⚠️ 스텁(미작성) | YYYY-MM-DD | todo/fill |
  ```
  통계 블록의 스텁 카운트와 총 노트 수도 함께 갱신한다.
- **스텁이 없으면:** 이 단계를 건너뛴다.

Step 6으로 진행한다.

---

### Step 5B — Inbox 이동 및 분해 위임
판정이 **복수 개념**인 경우에 수행한다.

1. 초안 내용을 `01_Inbox/` 에 새 파일로 저장한다.
   - 파일명: 스텁 파일명에서 `@` 없이 그대로 사용 (예: `스텁노트명.md`)
2. `03_Wiki/`의 원본 스텁 파일을 삭제한다.
3. `03_Wiki/index.md`에서 해당 스텁 항목을 제거한다.
4. 사용자에게 아래 안내를 출력하고 Step 6으로 진행한다.

```
📥 `스텁노트명.md` → 01_Inbox/로 이동 완료.
복수 개념이 포함되어 있습니다. `/process_inbox` 명령으로 분해하세요.
```

---

### Step 6 — index.md 및 log.md 업데이트
Step 5A 또는 Step 5B를 수행한 경우(건너뛰기가 아닌 경우)에만 아래를 갱신한다.

- **index.md (Step 5A):** 해당 노트의 태그 컬럼에서 `todo/fill` 제거 및 요약 업데이트.
- **index.md (Step 5B):** 이미 Step 5B에서 항목 제거 완료. 추가 갱신 불필요.
- **log.md:** 맨 하단에 Append (기존 내용 수정 금지).
  ```
  ## [YYYY-MM-DD] fill-stubs | 스텁 보완
  - 완료(저장): `노트명.md`   ← Step 5A인 경우
  - 완료(분해위임): `노트명.md` → 01_Inbox/   ← Step 5B인 경우
  - 신규 스텁 생성: N건 (`스텁명1.md`, `스텁명2.md`)   ← Step 5A-1에서 생성된 경우만
  - 잔여 스텁: N개 (다음 /fill-stubs 실행 시 처리)
  ```
  > 신규 스텁이 없으면 `신규 스텁 생성` 줄은 생략한다.

---

### Step 7 — 결과 보고 및 종료
처리 결과를 요약 출력하고 종료한다.

```
✅ 완료(저장): `노트명.md`              ← Step 5A인 경우
📥 완료(분해위임): `노트명.md`          ← Step 5B인 경우
📋 잔여 스텁: N개 — 다음 /fill-stubs 실행 시 처리됩니다.
```
