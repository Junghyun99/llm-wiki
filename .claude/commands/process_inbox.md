# Description: 01_Inbox의 첫 번째 파일 하나를 읽고 Zettelkasten으로 변환 후 원본을 02_Raw_Sources로 보관합니다.

## 실행 파이프라인 (Execution Pipeline)

너는 지금부터 `/process-inbox` 명령을 수행한다. 너에게 부여된 파일 조작 도구(File Write, Bash 등)를 활용하여 아래 단계를 엄격히 순차적으로 실행하라.

### 1단계: 대기열 확인

`01_Inbox/` 디렉터리를 스캔하여 처리 가능한 파일 목록을 수집한다.
(`.gitkeep`, `.DS_Store` 등 숨김·시스템 파일 제외)

파일이 없다면:
```
📥 처리할 파일이 없습니다. 01_Inbox/ 가 비어 있습니다.
```
를 출력하고 즉시 종료한다.

파일이 있다면 **목록 중 첫 번째 파일 하나만** 선택한다.
나머지 파일이 있을 경우 아래 안내를 출력한다:
```
📥 대기 중인 파일: N개
→ 이번 실행에서 처리할 파일: `첫번째파일명` (1개)
→ 나머지 N-1개는 다음 /process-inbox 실행 시 처리됩니다.
```

### 2단계: 사전 검토 요청 (Preview)

선택된 파일의 내용을 읽고, 아래 형식으로 사용자에게 검토를 요청한다.
**사용자의 승인 또는 피드백을 받기 전까지 절대 파일을 생성하지 마라.**

```
📄 처리 대상: `파일명`

**📝 핵심 요약 (3~4문장)**
[원본 문서의 핵심 내용 요약]

**🗂️ 생성 예정 문헌 노트 (1개)**
- `@파일명.md`

**🧠 추출 예정 영구 노트 (N개)**
- `개념명1.md` — 한 줄 설명
- `개념명2.md` — 한 줄 설명
- `개념명3.md` — 한 줄 설명

**⚠️ 충돌 감지 결과** (충돌 없을 시 이 항목은 생략)
- `기존노트명.md`의 "기존 내용" ↔ 새 소스의 "충돌 내용" — 판단 필요

진행할까요? (수정 요청 또는 승인)
```

- 사용자가 **승인**하면 3단계로 진행한다.
- 사용자가 **피드백**을 주면 반영하여 Preview를 다시 출력하고 재승인을 요청한다.

### 3단계: 지식 추출 및 파일 생성

사용자 승인이 확인된 구성대로 `.claude/skills/extract-zettelkasten/SKILL.md`의 규칙을 적용하여 `03_Wiki/` 루트 경로에 각각의 `.md` 파일들을 물리적으로 생성(Write)한다.

### 4단계: 원본 아카이빙

```bash
mkdir -p 02_Raw_Sources/$(date +%Y-%m)
mv 01_Inbox/[처리된파일명] 02_Raw_Sources/$(date +%Y-%m)/
```

### 5단계: index.md 업데이트

`03_Wiki/index.md`를 열어 새롭게 생성된 노트들을 해당 카테고리 테이블(문헌/영구/MOC)에 추가하고, 하단 통계(총 노트 수, 마지막 업데이트일)를 갱신한다.

### 6단계: log.md 기록

`03_Wiki/log.md` 맨 **하단**에 아래 형식으로 이번 작업 이력을 추가(Append)한다. 기존 내용 수정 금지.

```
## [YYYY-MM-DD] ingest | 원본 파일명
- 원본 파일: `01_Inbox/파일명`
- 생성된 노트: N개 (문헌 X, 영구 Y, MOC Z)
  - `@문헌노트명.md`
  - `영구노트명1.md`
  - `영구노트명2.md`
- 아카이빙: `02_Raw_Sources/YYYY-MM/파일명`
```

### 7단계: 결과 보고

```
✅ 처리 완료: `파일명`
- 생성된 노트: N개
  - `@문헌노트명.md`
  - `영구노트명1.md`
  - `영구노트명2.md`
- 아카이빙: `02_Raw_Sources/YYYY-MM/파일명`

📥 01_Inbox 잔여 파일: N-1개 → /process-inbox 를 다시 실행하세요.
```
