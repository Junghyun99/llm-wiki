# Description: 01_Inbox의 파일들을 file-ingester 서브에이전트에 하나씩 위임하여 컨텍스트 오염 없이 처리합니다.

## 실행 파이프라인 (Orchestrator)

너는 지금부터 `/process-inbox` 오케스트레이터 역할을 수행한다.
각 파일의 실제 처리는 `file-ingester` 서브에이전트에 위임하며,
너는 파일 목록 관리와 최종 결과 보고만 담당한다.

### 왜 서브에이전트인가?

Inbox에는 주제가 완전히 다른 파일들(예: 세법 + 주식 + 의학)이 섞여 들어올 수 있다.
단일 컨텍스트에서 순차 처리하면 이전 파일의 주제·어조·해석 방향이 다음 파일 처리에
은연중 영향을 준다(컨텍스트 오염). `file-ingester` 서브에이전트는 매번 독립적인
컨텍스트에서 시작하므로 파일 간 오염이 원천 차단된다.
또한 각 서브에이전트는 처리 후 `index.md`를 갱신하므로, 다음 서브에이전트는
갱신된 index.md를 읽어 현재 위키 전체 상태를 파악하고 충돌 감지를 수행한다.

---

## 1단계: 대기열 확인

`01_Inbox/` 디렉터리를 스캔하여 처리할 파일 목록을 수집한다.
(`.gitkeep`, `.DS_Store` 등 숨김 파일 및 시스템 파일은 제외)

파일이 없다면:
```
📥 처리할 파일이 없습니다. 01_Inbox/ 가 비어 있습니다.
```
를 출력하고 즉시 종료한다.

파일이 N개 있다면 아래 형식으로 목록을 출력한다:
```
📥 처리 대기열: N개 파일 발견
1. 파일명A.md
2. 파일명B.pdf
3. 파일명C.txt
...

각 파일을 독립 컨텍스트(file-ingester 서브에이전트)로 순차 처리합니다.
```

---

## 2단계: 파일별 서브에이전트 위임 (순차 처리)

파일 목록을 순서대로 순회하며, **한 번에 하나씩** `file-ingester` 서브에이전트에 위임한다.

다음 파일의 서브에이전트는 **반드시 이전 서브에이전트가 완전히 종료된 후** 시작한다.
(이전 서브에이전트가 index.md를 갱신한 뒤, 다음 서브에이전트가 그 갱신된 index.md를 읽어야 충돌 감지가 정확하다)

각 서브에이전트 위임 시 아래 형식으로 태스크를 전달한다:

```
처리 대상 파일: [파일명] (전체 N개 중 M번째)

01_Inbox/[파일명] 파일을 제텔카스텐 방법론으로 처리해줘.
file-ingester 서브에이전트 지침에 따라 Preview 생성 → 사용자 승인 → 
파일 생성 → 아카이빙 → index.md 및 log.md 갱신 순서로 진행하고,
완료 후 결과 요약을 반환해줘.
```

각 서브에이전트로부터 결과를 수신하면 임시로 기록해 두고 다음 파일로 진행한다.

---

모든 파일 처리가 완료되면 아래 형식으로 이번 실행의 전체 결과를 출력한다.
