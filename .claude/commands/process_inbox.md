# Description: 01_Inbox의 파일을 읽고 Zettelkasten으로 변환 후 원본을 02_Raw_Sources로 보관합니다.

## 실행 파이프라인 (Execution Pipeline)
너는 지금부터 `/process-inbox` 명령을 수행한다. 너에게 부여된 파일 조작 도구(File Write, Bash 등)를 활용하여 아래 단계를 엄격히 순차적으로 실행하라.

1. **대기열 확인:** 
   `01_Inbox/` 디렉터리의 파일 목록을 스캔한다. 파일이 없다면 "📥 처리할 파일이 없습니다."라고 출력하고 매크로를 즉시 종료한다.
   파일이 N개라면, 아래 2~6단계를 **파일 하나씩 순서대로 N번 반복**한다.
   **절대 여러 파일을 동시에 읽거나 동시에 처리하지 않는다.**

2. **사전 검토 요청 (Preview):**
   ⚠️ **한 번에 반드시 하나의 파일만 처리한다.**
   대기열에서 **현재 순번의 파일 하나만** 내용을 읽고, 아래 형식으로 사용자에게 검토를 요청한다.
   이 파일의 3~6단계가 완전히 끝나기 전까지는 다음 파일을 절대 읽지 않는다.
   사용자의 승인 또는 피드백을 받기 전까지 절대 파일을 생성하지 마라.

   ```
   📄 처리 대상: `파일명` (N개 중 M번째)

   **📝 핵심 요약 (3~4문장)**
   [원본 문서의 핵심 내용 요약]

   **🗂️ 생성 예정 문헌 노트 (1개)**
   - `@파일명.md`

   **🧠 추출 예정 영구 노트 (N개)**
   - `개념명1.md` — 한 줄 설명
   - `개념명2.md` — 한 줄 설명
   - `개념명3.md` — 한 줄 설명

   **⚠️ 충돌 감지 결과** (충돌 없을 시 이 항목은 생략)
   - `기존노트명.md`의 "기존 내용" ↔ 새 소스의 "충돌 내용" — 판단 필요

   진행할까요? (수정 요청 또는 승인)
   ```

   - 사용자가 **승인**하면 3단계로 진행한다.
   - 사용자가 **피드백**을 주면 (예: "이 개념은 빼줘", "이 부분을 강조해줘") 반영하여 Preview를 다시 출력하고 재승인을 요청한다.

3. **지식 추출 및 파일 생성:**
   사용자 승인이 확인된 구성대로 `.claude/skills/extract_zettelkasten.md`의 규칙을 적용하여 `03_Wiki/` 루트 경로에 각각의 `.md` 파일들을 물리적으로 생성(Write)한다.

4. **원본 아카이빙 (Bash 처리):**
   위키 생성이 완료된 원본 파일들을 보관소로 치운다.
   - Bash 명령어를 사용하여 현재 시스템의 연-월을 구한다. (예: `date +%Y-%m`)
   - `02_Raw_Sources/YYYY-MM/` 형식의 폴더가 존재하는지 확인하고, 없다면 생성한다 (`mkdir -p 02_Raw_Sources/$(date +%Y-%m)`).
   - 처리가 끝난 `01_Inbox/` 내의 원본 파일을 해당 연월 폴더로 이동시킨다 (`mv`).

5. **index.md 업데이트:**
   `03_Wiki/index.md`를 열어 새롭게 생성된 노트들을 해당 카테고리 테이블(문헌/영구/MOC)에 추가하고, 하단 통계(총 노트 수, 마지막 업데이트일)를 갱신한다.

6. **log.md 기록:**
   `03_Wiki/log.md` 맨 하단에 아래 형식으로 이번 작업 이력을 추가(Append)한다.
   ```
   ## [YYYY-MM-DD] ingest | 원본 파일명
   - 원본 파일: `경로`
   - 생성된 노트: N개 (문헌 X, 영구 Y, MOC Z)
   - 아카이빙: `02_Raw_Sources/YYYY-MM/파일명`
   ```

   6단계까지 완료되면, 대기열에 다음 파일이 있을 경우 2단계로 돌아가 반복한다.

7. **결과 보고:**
   모든 파일의 처리가 완료되면, 이번 실행에서 생성된 전체 `@문헌` 노트와 `영구 노트`들의 목록을 사용자에게 요약 출력하라.
