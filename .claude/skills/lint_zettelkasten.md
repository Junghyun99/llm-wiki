# 스킬명: lint_zettelkasten
# 목적: 03_Wiki/ 내부의 제텔카스텐 노트들을 주기적으로 스캔하여 구조적 무결성을 확보하고 지식을 최적화(Refactoring)한다.

## 1. 기본 원칙 (Core Principles)
너는 정원사(Gardener)처럼 지식망을 다듬는다. 기존에 작성된 사용자의 지식이나 인사이트를 임의로 삭제해서는 안 되며, 연결성을 강화하고 중복을 제거하는 데 집중한다.
* 작업 대상은 오직 `03_Wiki/` 루트 디렉터리에 있는 마크다운 파일들이다.
* 작업을 수행한 후에는 반드시 어떤 파일이 어떻게 변경되었는지 요약 리포트를 출력해야 한다.

## 2. 유지보수 4대 핵심 로직 (Maintenance Workflows)

### Task A: 중복 개념의 병합 (Deduplication & Merge)
* **조건:** 두 개 이상의 영구 노트가 내용상 80% 이상 일치하거나 완전히 동일한 개념을 다루고 있을 때. (예: `ISA_세제혜택.md` 와 `ISA_비과세_한도.md`)
* **행동:**
  1. 두 문서의 내용을 통합하여 더 포괄적이고 명확한 이름의 새로운 영구 노트를 생성한다.
  2. YAML 프론트매터의 `aliases:` 에 기존 문서들의 이름을 추가하여 검색되게 한다.
  3. **[중요]** 기존 노트들을 참조하고 있던 다른 모든 문서들의 양방향 링크(`[[ ]]`)를 새 노트의 이름으로 일괄 업데이트한다.
  4. 통합이 완료된 기존 중복 노트들은 삭제한다.

### Task B: 고립 노드 구출 (Orphan Rescue)
* **조건:** 다른 영구 노트나 MOC(목차) 노트와 전혀 연결되지 않은 채, 오직 출처(`@문헌`) 링크만 덩그러니 있는 고립된 영구 노트를 발견했을 때.
* **행동:**
  1. 해당 노트의 내용을 분석한다.
  2. 시스템 내에 존재하는 가장 적절한 허브 노트(`MOC_주제명`)를 찾아 문서 하단에 `관련 목차: [[MOC_주제명]]` 링크를 강제로 삽입한다.
  3. 적절한 MOC가 없다면, 관련된 다른 영구 노트에 링크를 연결하여 섬(Island) 상태를 해소한다.

### Task C: 링크 무결성 검사 및 복구 (Dead Link Fix)
* **조건:** 본문에 `[[특정_개념]]`이라고 링크가 걸려 있으나, 실제 `03_Wiki/` 폴더에 `특정_개념.md` 파일이 존재하지 않는 경우 (Dead Link).
* **행동:**
  1. 단순 오탈자나 띄어쓰기 문제라면 올바른 기존 파일명으로 링크 텍스트를 수정한다.
  2. 실제로 누락된 핵심 개념이라면, `특정_개념.md` 라는 이름의 빈 스텁(Stub) 노트를 생성하고 `#todo/fill` 태그를 달아둔다.

### Task D: MOC (허브 노트) 최신화
* **조건:** `MOC_` 접두사가 붙은 허브 노트들.
* **행동:**
  1. 새롭게 생성되거나 병합된 영구 노트들이 해당 MOC의 주제와 부합한다면, MOC 문서 내부의 리스트(`- [[ ]]`)에 누락 없이 추가하여 목차로서의 기능을 최신 상태로 유지한다.
  2. MOC 신규 생성 시 `extract-zettelkasten` 스킬의 **[MOC 노트 양식 예시]** 를 반드시 따른다. (YAML 프론트매터 + 본문 구조)
  3. MOC 내용이 변경될 때마다 YAML 프론트매터의 `date_updated` 필드를 오늘 날짜(YYYY-MM-DD)로 갱신한다.

### Task E: 모순·충돌 감지 (Contradiction Detection)
* **조건:** 위키 전체 스캔 중 동일하거나 관련된 개념을 다루는 노트들 사이에서 아래 유형의 충돌이 발견될 때.
  - **수치 충돌:** 동일 개념에 대해 날짜, 금액, 비율 등 구체적 수치가 다른 경우
  - **사실 충돌:** 동일 개념에 대해 반대되는 사실을 주장하는 경우
  - **구조 충돌:** 동일 개념의 분류나 정의가 서로 다른 경우
* **행동:**
  1. 충돌하는 두 노트를 특정하고 각각의 관련 문장을 추출한다.
  2. 두 노트 중 더 최신(`date_created` 기준)이거나 더 신뢰할 수 있는 출처(`source` 기준)를 판단한다.
  3. **[중요]** 자동으로 수정하지 않는다. 리포트에 충돌 내용을 명시하고 사용자가 직접 판단하도록 한다.
  4. 충돌이 감지된 노트에 `#conflict` 태그를 YAML 프론트매터에 추가하여 표시해둔다.

## 3. index.md 갱신 규칙
파일 조작(생성·병합·삭제)이 발생할 때마다 `03_Wiki/index.md`를 반드시 동기화한다.
* **노트 병합(Task A):** 기존 두 행을 삭제하고, 통합 노트의 새 행을 해당 테이블에 추가한다. `aliases`에 기존 이름이 등록되어 있으므로 요약은 더 포괄적으로 작성한다.
* **스텁 노트 생성(Task C):** `## 🧠 영구 노트` 테이블에 `#todo/fill` 표시와 함께 행을 추가한다.
  ```
  | [[파일명]] | ⚠️ 스텁(미작성) | YYYY-MM-DD | todo/fill |
  ```
* **모든 작업 후:** 하단 `## 📊 통계` 블록의 총 노트 수와 마지막 업데이트일을 갱신한다.

## 4. log.md 기록 규칙
모든 파일 조작이 완료된 후 `03_Wiki/log.md` 맨 **하단**에 아래 형식으로 항목을 추가(Append)한다. 기존 내용을 절대 수정하지 마라.

```
## [YYYY-MM-DD] lint | 정비 요약 한 줄
- 병합: N건 (`노트A` + `노트B` → `통합노트C`)
- 고립 구출: N건 (`고립노트` → `[[MOC_주제]]`)
- 데드링크 복구: N건 (수정 X건, 스텁 생성 Y건)
- MOC 최신화: N건
- 충돌 감지: N건 (`#conflict` 태그 추가, 사용자 판단 필요)
```

## 5. 최종 출력 형식 (Execution Report)
파일 시스템 조작(수정, 생성, 삭제)을 마친 후, 사용자에게 다음과 같은 형태의 유지보수 리포트를 마크다운으로 출력하라.

### 🧹 주간 제텔카스텐 정비 리포트
* **🔄 병합됨:** `노트A` + `노트B` ➡️ `통합노트C` (관련 링크 3건 업데이트 완료)
* **🔗 구출됨:** `고립노트D` ➡️ `[[MOC_관련주제]]` 에 연결 완료
* **🛠️ 복구됨:** 2개의 끊어진 링크를 수정하고, 1개의 빈 스텁 노트 생성 완료
* **⚠️ 충돌 감지됨:** `노트E`("기존 내용") ↔ `노트F`("충돌 내용") — 사용자 판단 필요 (`#conflict` 태그 추가 완료)
* **📭 미작성 스텁 목록:** `/fill-stubs` 명령으로 웹 검색 보완 가능
  - `스텁노트1.md`
  - `스텁노트2.md`
