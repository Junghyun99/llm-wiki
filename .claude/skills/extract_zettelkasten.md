# 스킬명: extract_zettelkasten
# 목적: 원본 문서를 제텔카스텐 방법론에 따라 문헌 노트(1개)와 원자적 영구 노트(N개)로 분해 및 마크다운 변환

## 1. 기본 원칙 (Core Principles)
너는 입력받은 텍스트나 문서를 단순 요약하는 것이 아니라, **'독립적으로 가치 있는 지식의 조각(원자성)'**으로 해체해야 한다.
* 모든 출력물은 Obsidian 호환 마크다운 파일 양식이어야 한다.
* 생성되는 모든 파일은 `03_Wiki/` 루트 디렉터리에 저장될 것을 전제로 작성한다. 하위 폴더 경로는 절대 적지 마라.
* 수식은 LaTeX 형식(`$$`)을 사용하고, 코드는 반드시 적절한 언어 태그(예: `python`, `yaml`)를 포함한 코드 블록으로 작성한다.

## 2. 작업 순서 (Workflow)

### 단계 1: 문헌 노트(Literature Note) 생성
먼저 원본 문서 전체를 대표하는 '문헌 노트'를 1개 작성한다.
* **파일명 규칙:** `@원문_제목.md` (반드시 `@`로 시작)
* **내용 구성:**
  1. 원본의 핵심 주제를 3~4문장으로 요약.
  2. 이 문서에서 추출해 낸 '영구 노트'들의 링크(`[[ ]]`) 목록.

### 단계 2: 영구 노트(Permanent Notes) 추출 및 생성
문서 내에서 기술적 아키텍처, 트레이딩 전략, 세제 혜택, 법률적 사실 등 독립적인 가치를 지닌 개념을 3~5개 추출하여 각각 별도의 파일로 생성한다.
* **파일명 규칙:** `개념_이름.md` (접두사 없음, 띄어쓰기 대신 언더바 `_` 권장)
* **원자성(Atomicity) 준수:** 각 노트는 원본 문서를 보지 않고도 그 자체로 이해될 수 있도록 완결성을 가져야 하며, 2~4개의 문단으로 짧고 명확하게 작성한다.
* **출처 명시:** 파일 하단에 반드시 부모 문헌 노트로 돌아가는 링크(`[[@원문_제목]]`)를 기재한다.

## 3. YAML 프론트매터(Frontmatter) 표준 양식
생성하는 모든 파일의 최상단에는 아래의 YAML 프론트매터를 정확히 삽입하라.

**[문헌 노트 양식 예시]**
```yaml
---
aliases: [원본의 다른 이름이나 약어]
tags: [source/pdf, source/article, 분야명]
date_processed: YYYY-MM-DD
author: 원작자 또는 출처기관
---
```

**[영구 노트 양식 예시]**
```yaml
---
aliases: [개념의 동의어, 영문명]
tags: [permanent, 세금, 자동화, 파이썬 등 핵심키워드 1~2개]
date_created: YYYY-MM-DD
source: "[[@원문_제목]]"
---
```

## 4. 양방향 링크 및 허브(MOC) 연결 가이드
* 본문을 작성할 때, 시스템에 이미 존재할 법한 범용적인 핵심어(예: [[Python]], [[ISA]], [[Github_Actions]], [[백테스팅]])에는 적극적으로 브라켓(`[[ ]]`)을 씌워라.
* 추출한 영구 노트가 특정 대주제에 속한다고 판단되면, 문서 맨 밑에 관련 목차: `[[MOC_대주제명]]` (예: `[[MOC_퀀트트레이딩]]`, `[[MOC_연금세무]]`) 링크를 하나 이상 추가하라.

## 5. 모순·충돌 감지 (Contradiction Detection)
노트 구성이 끝나면 파일을 생성하기 전에 기존 위키와 충돌 여부를 반드시 검사한다.

* **대상 선정:** `03_Wiki/index.md`를 읽어 추출 예정 영구 노트의 개념과 관련된 기존 노트를 2~5개 추려낸다. 위키 전체를 스캔하지 않는다.
* **비교 기준:** 추려낸 기존 노트를 열어 아래 유형의 충돌을 탐지한다.
  - **수치 충돌:** 날짜, 금액, 비율 등 구체적 수치가 다른 경우 (예: 한도 2000만원 vs 4000만원)
  - **사실 충돌:** 동일 개념에 대해 반대되는 사실을 주장하는 경우
  - **구조 충돌:** 동일 개념의 분류나 정의가 다른 경우
* **충돌 발견 시:** 파일 생성을 중단하고 `/process-inbox`의 Preview 단계로 결과를 전달하여 사용자에게 보고한다. 사용자 판단 후 진행한다.
* **충돌 없을 시:** 그대로 파일 생성 단계로 진행한다.

## 6. index.md 업데이트 규칙
노트 생성이 완료되면 반드시 `03_Wiki/index.md`를 열어 아래 규칙에 따라 갱신한다.
* **문헌 노트**는 `## 🗂️ 문헌 노트` 테이블에 행을 추가한다.
  ```
  | [[@파일명]] | 한 줄 요약 | YYYY-MM-DD | 저자명 |
  ```
* **영구 노트**는 `## 🧠 영구 노트` 테이블에 행을 추가한다.
  ```
  | [[파일명]] | 한 줄 요약 | YYYY-MM-DD | 핵심태그1, 태그2 |
  ```
* **MOC 노트**는 `## 🗺️ 허브 노트` 테이블에 행을 추가한다.
  ```
  | [[MOC_파일명]] | 커버 범위 설명 | 연결된 노트 수(숫자) |
  ```
* 하단 `## 📊 통계` 블록의 총 노트 수, 각 유형별 카운트, 마지막 업데이트일을 갱신한다.

## 6. log.md 기록 규칙
index.md 갱신이 끝나면 `03_Wiki/log.md` 맨 **하단**에 아래 형식을 그대로 사용하여 항목을 추가(Append)한다. 기존 내용을 절대 수정하지 마라.

```
## [YYYY-MM-DD] ingest | 원본_파일명(확장자 포함)
- 원본 파일: `경로/파일명`
- 생성된 노트: N개 (문헌 X, 영구 Y, MOC Z)
  - `@문헌노트명.md`
  - `영구노트명1.md`
  - `영구노트명2.md`
- 아카이빙: `02_Raw_Sources/YYYY-MM/파일명`
```

## 7. 최종 출력 형식
명령어 실행 시, 생성해야 할 각 파일의 이름과 내용을 명확히 구분하여 코드 블록 형태로 출력하거나, 파일 시스템 권한이 있다면 `03_Wiki/` 디렉터리에 직접 분할하여 `.md` 파일로 저장하라.
