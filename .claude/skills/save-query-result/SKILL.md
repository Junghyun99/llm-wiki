# save-query-result

`/ask` 쿼리 답변 후 **저장 가치 판단 → 제안 → 사용자 승인 → 영구 노트 생성**까지 처리하는 스킬.

---

## 1. 저장 가치 판단 기준 (Save-Worthiness Criteria)

답변 완료 후 아래 기준을 체크하여 **2개 이상** 해당하면 저장을 제안한다. 1개 이하면 제안하지 않는다.

* **다중 참조:** 답변 생성 시 2개 이상의 위키 노트를 종합했는가?
* **비교·분석:** 두 개 이상의 개념을 비교하거나 구조적 분석을 수행했는가? (예: "A vs B", "~의 장단점", "~를 분석해줘")
* **새로운 연결:** 기존 위키에 없던 개념 간 연결고리나 인사이트가 포함되었는가?
* **완결성:** 답변이 원자적 개념 노트로서 독립적으로 읽힐 수 있는 완결성을 갖추었는가?
* **사용자 명시 요청:** 사용자가 "정리해줘", "분석해줘", "비교해줘", "요약해줘" 등 명시적 정리 의도를 표현했는가?

---

## 2. 저장 제안 방식

판단 기준을 충족하면 답변 말미에 아래 형식으로 저장을 제안한다. 강요하지 않으며 사용자가 거절하면 즉시 종료한다.

```
💾 이 답변을 위키에 저장할까요?
파일명 제안: `제안_파일명.md`
```

---

## 3. 저장 노트 작성 규칙

사용자가 승인하면 아래 규칙에 따라 `03_Wiki/`에 영구 노트를 생성한다.

* **파일명:** 사용자가 별도 지정하지 않으면 제안한 파일명을 사용한다. 띄어쓰기 대신 언더바 `_` 사용.
* **노트 유형:** 기본적으로 영구 노트(접두사 없음)로 저장한다. 단, 여러 개념의 목차 역할이라면 `MOC_` 접두사를 사용한다.
* **YAML 프론트매터:**
  ```yaml
  ---
  aliases: [질문의 다른 표현, 핵심 키워드]
  tags: [query-result, 핵심태그1, 태그2]
  date_created: YYYY-MM-DD
  source: "query"
  references: ["[[참조노트1]]", "[[참조노트2]]"]
  ---
  ```
* **본문 구성:**
  1. 질문 컨텍스트를 한 문장으로 명시 (예: "이 노트는 ~에 대한 쿼리 결과를 정리한 것이다.")
  2. 답변 내용을 원자적 개념 단위로 재구성. 채팅 말투("~입니다")를 지식 서술 말투("~이다")로 변환한다.
  3. 참조한 위키 노트들을 `[[파일명]]` 형식으로 본문에 명시.
  4. 파일 하단에 관련 MOC 링크 추가.

---

## 4. index.md 및 log.md 업데이트

노트 저장 후 반드시 아래 두 파일을 갱신한다.

* **index.md:** `## 🧠 영구 노트` 테이블에 새 행 추가. 태그 컬럼에 `query-result` 명시.
* **log.md:** 맨 하단에 아래 형식으로 Append.
  ```
  ## [YYYY-MM-DD] query | 질문 핵심 키워드
  - 참조 파일: `파일명1.md`, `파일명2.md`
  - 저장됨: `생성된_노트명.md`
  ```
